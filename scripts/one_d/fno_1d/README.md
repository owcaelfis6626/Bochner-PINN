# SPDE-FNO

A Fourier Neural Operator companion to the PINN side of this repo.

## What it does

Learns the operator
```
G : (noise_z, noise_y, noise_p, jump_z, jump_y, IC) -> (Z, Y, P)
```
on the same fixed (Nx, Nt) grid as the PINN. One trained model
amortizes over noise realizations: evaluating an ensemble is one batched
forward pass instead of retraining a network per seed.

The training data is generated by the existing classical FD solver
(`../classical_solver.py`), with optional Variance-Gamma jumps on `z`
and Gamma-process jumps on `y` (`../vg_jumps.py`). Inputs are stacked
into 8 channels; outputs are 3 channels.

## Why FNO for this problem

- **Spectral by construction.** Our metric is distributional spectral
  matching (log-MSE on spatial / temporal PSDs); FNO's spectral convolution
  layers operate in exactly that space.
- **Amortized ensemble.** No more "12 models, bimodal across seeds":
  one model, one number. Variance across realizations is folded into
  the training distribution.
- **Direct PINN comparison.** Eval reports the same `sp_err` / `tp_err`
  the PINN side reports, so the headline plot is FD vs PINN vs FNO.

## Files

| File              | Role                                                   |
| ----------------- | ------------------------------------------------------ |
| `config_fno.py`   | FNOConfig dataclass — modes, width, dataset sizes      |
| `fno_model.py`    | `SpectralConv2d`, `FNOBlock`, `FNO2d`                  |
| `fno_dataset.py`  | Dataset generator, per-channel normaliser, caching     |
| `fno_losses.py`   | Composite loss: MSE + log-PSD (x, t) + mean/var        |
| `fno_train.py`    | Supervised training loop, best-val checkpointing       |
| `fno_eval.py`     | Distributional spectral metric on held-out test split  |
| `main_fno.py`     | CLI driver for full pipeline                           |

## Usage

```bash
# Smoke test (≈1 minute on a GPU)
python main_fno.py --quick

# Full run
python main_fno.py

# Re-evaluate from saved checkpoint without retraining
python main_fno.py --eval-only
```

## Default architecture

| Hyperparameter | Value |
| -------------- | ----- |
| modes_x        | 16    |
| modes_t        | 24    |
| width          | 32    |
| n_layers       | 4     |
| activation     | gelu  |

Yields ~250k parameters — comparable to the PINN's 112k, well within
GPU budget for 256 train + 64 val + 256 test on a 128×512 grid.

## How this slots into the paper

Three rows in the headline table:

| Method            | sp_err (z) | tp_err (z) | comment                  |
| ----------------- | ---------- | ---------- | ------------------------ |
| PINN baseline (v12) | ~0.06      | ~0.71      | no jumps                 |
| PINN + VG/Gamma (v23) | TBD     | TBD        | jumps on z and y         |
| FNO (this folder)   | TBD       | TBD        | amortized over ensemble  |

If FNO wins on `tp_err` it directly demonstrates the bimodality
problem was about *training the operator one realization at a time*,
not about the SPDE itself.
